00과목 개요

코드를 ‘배우는’ 수업이 아니라, 만들고 싶은 것을 만들다가 막히는 지점에서 필요한 개념을 가져다 쓰는 수업입니다.

개발 환경
Python 3 · pip install pygame-ce. 표준 pygame이 아닌 커뮤니티 에디션을 사용하며, import pygame 문법은 동일합니다.
수업 구조
주 3차시(총 45차시) · 1부 기초 실습(1~7주) → 중간고사(8주) → 2부 심화 기술(9~11주) → 3부 개인 프로젝트(12~15주).
자료 형태
모든 실습 자료는 이미지·사운드·코드가 내장된 단일 HTML 파일이라 인터넷 없이 열어도 그대로 동작합니다.
최종 산출물
학생 한 명당 하나씩 만드는 오리지널 게임과, 그 게임이 자동으로 실행되는 라즈베리파이 휴대용 게임기 실물.
한글 렌더링 규칙 — 게임 화면에 한글을 그릴 때는 pygame.font.SysFont("malgungothic", ...) 대신 배포된 assets/NanumGothic-Regular.ttf를 pygame.font.Font로 로드합니다. 모든 실습 코드가 이 규칙을 따르며, 라즈베리파이로 이식할 때 폰트가 깨지지 않는 이유이기도 합니다.

01학습 목표

학기가 끝났을 때 학생이 할 수 있게 되는 것들입니다.

게임 루프를 설계한다
입력 → 갱신 → 충돌 → 렌더 → 대기의 5단계를 스스로 배치하고, 프레임률과 무관한 이동을 델타타임으로 보장한다.
충돌을 상황에 맞게 고른다
AABB·원·픽셀 마스크의 정확도와 비용을 비교해 필요한 곳에만 정밀 판정을 쓴다.
구조로 복잡도를 감당한다
FSM 씬 관리, 오브젝트 풀링, 데이터 주도 설계로 코드가 커져도 무너지지 않게 만든다.
근거를 갖고 최적화한다
감이 아니라 cProfile과 FPS 측정으로 병목을 찾고, 고친 뒤 다시 측정해 확인한다.
소프트웨어를 하드웨어와 잇는다
GPIO 버튼 입력을 게임 입력으로 합치고, 부팅 시 자동 실행되는 완제품 형태로 배포한다.
혼자 끝까지 완주한다
만들 수 있는 크기로 범위를 좁혀 기획하고, 기획부터 하드웨어까지 스스로 책임지고, 만든 것을 남에게 설명하고, 남의 작품을 기준을 갖고 평가한다.

04수업 중 과제 — 주차별 통합 과제 30%

매주 나오는 과제는 연습 문제가 아니라 그 주에 배운 내용을 근거로 만드는 작동하는 게임입니다. 실습에서 따라 친 조각들을 하나로 합쳐 ‘끝까지 플레이되는 것’을 만들어 제출합니다.

통합 과제란 — 예를 들어 2주차 ‘미로 탈출 타임어택’은 실습1의 카운트다운, 실습2의 걷기 애니메이션, 그리고 벽에 막히는 이동을 한 게임 안에 모두 넣어야 완성됩니다. 실습 자료에 과제 조건과 힌트가 함께 실려 있고, 정답 예시 코드는 제출 마감 이후에 열립니다.

05게임 문제 해결 30%

12~15주 개인 프로젝트에 해당하며, 게임기 제작 15% · 발표 8% · 동료평가 7%로 나눕니다.

게임기 제작 15%

평가 항목배점기준
문제 정의와 기획3한 줄로 설명되는 콘셉트가 있고, 15주 안에 만들 수 있는 크기로 범위를 좁혔는가
게임 완성도5시작-플레이-종료가 끊기지 않고, 승패 조건과 피드백(소리·연출)이 갖춰졌는가
기술 적용32부 심화 기술(FSM·풀링·데이터 주도·저장) 중 최소 2가지를 근거 있게 적용했는가
하드웨어 통합3GPIO 버튼으로 조작되고, 전원을 켜면 자동 실행되며, 안전 종료가 가능한가
문제 해결 기록1이식·통합 과정에서 막힌 지점과 해결 과정을 기록으로 남겼는가

발표 8%

평가 항목배점기준
문제와 해법의 연결3왜 이 게임을 만들었는지, 그 의도가 게임 안에서 어떻게 구현됐는지 설명되는가
기술 설명3가장 어려웠던 기술적 난관과 해결 과정을 남이 알아듣게 설명하는가
시연과 응답2실물 게임기로 안정적으로 시연하고 질문에 답하는가

동료평가 7%

다른 학생의 작품을 평가한 결과(5%)와, 평가자로서의 성실성(2%)으로 구성합니다. 받는 점수뿐 아니라 매기는 점수의 질도 함께 봅니다.

구분배점평가 방법
작품 평가5재미 · 완성도 · 조작감 · 독창성 4개 항목을 5점 척도로 채점하고, 항목마다 한 문장 근거를 적는다. 근거 없는 점수는 무효 처리한다.
평가자 성실성2배정된 작품을 빠짐없이 평가했는가, 근거 문장이 ‘재밌다’ 수준을 넘어 무엇이 어떻게 좋고 아쉬운지 짚는가.
동료평가를 하는 이유 — 점수를 매기기 위해서가 아니라, 남의 게임을 ‘플레이어’가 아닌 ‘만드는 사람’의 눈으로 보게 하기 위해서입니다. 그래서 점수보다 근거 문장을 더 중요하게 봅니다.

08운영 유의사항

pygame이 아니라 pygame-ce
모든 안내와 코드는 커뮤니티 에디션 기준입니다. 설치 명령은 pip install pygame-ce이며, 표준 pygame과 함께 설치하면 충돌하므로 하나만 남깁니다.
한글 입력기와 키 입력
macOS에서 한글 입력 소스는 키보드 레이아웃 전체를 재매핑하므로, 단축키는 event.key 대신 event.scancode == pygame.KSCAN_P 방식으로 처리합니다.
하드웨어 준비 시점
라즈베리파이·버튼·케이스는 12주 기획 확정 직후 1인 1세트로 배부해, 13주 이식 실습에 각자 실물이 준비되어 있게 합니다. 수량이 부족하면 13~14주에 한해 조별 순환 사용을 계획합니다.
진도 조절 여지
7주 코드 리뷰와 12주 기획은 조절 구간입니다. 앞 진도가 밀리면 이 두 주에서 보충하고, 순조로우면 프로토타입 완성도를 높이는 데 씁니다.
결석·미제출 처리
수업 중 과제는 다음 차시까지 지연 제출을 허용하되 확장 시도 항목을 제외합니다. 프로젝트 주차는 결석 시 진도 회복이 어려우므로 사전 협의와 별도 보충 시간을 원칙으로 합니다.
백업 습관
프로젝트 시작(12주)과 동시에 개인 저장소를 만들고, 매 차시 종료 시 커밋합니다. 이식 단계에서 되돌릴 지점이 없으면 복구가 어렵습니다.
